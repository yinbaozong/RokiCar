# RokiCar 用户刷写教程（三文件版）

本教程对应本仓库主固件目录 中的 `boot.py`、`main.py`、`rokicar_core.py`。请使用这三个文件，暂不采用之前的单文件版。车灯接法已由作者确认可用，保持现有程序和 D2 接线。

## 先分清两件事

这里的“刷固件”是把三份 Python 程序写进核心板的文件系统；不是用烧录器写入 `.bin` 镜像。核心板必须已有兼容的 MicroPython 环境，能够通过 USB 串口进入 REPL。不要为了上传这三份文件擦除 Flash，也不要随意给 CyberBrick 刷通用 ESP32 固件。

本包的 `boot.py` 已改为有限初始化；正常启动时由 MicroPython 自动执行 `main.py`。这是为了方便以后连接工具和更新程序，电机控制、灯光、协议和 Wi-Fi 参数未改。依据：[MicroPython 官方启动说明](https://docs.micropython.org/en/v1.26.0/reference/reset_boot.html)。

## 准备什么、安装什么

- CyberBrick 核心板、一根支持数据传输的 USB 线、电脑和本资料包。
- 初学者推荐 **Thonny**：[官网下载](https://thonny.org/)。Windows 常规安装版自带电脑端 Python，按下面的图形界面流程操作即可，不必另装 VS Code、Arduino IDE 或 esptool。
- 用命令行或让能控制本机的 AI 帮忙时，安装 [Python 3](https://www.python.org/downloads/windows/)，再安装官方 `mpremote` 工具。
- Windows 如果没有识别出串口，先换数据线/USB 口，再按设备硬件 ID 找对应官方驱动；不默认要求每块板安装 CH340/CP210x 驱动。
- 刷写和校准时架空三轮；更稳妥的文件上传阶段可以先断开电机电源，保留核心板 USB 供电。

## 方式一：Thonny 图形界面

1. 接好 USB，关闭占用该串口的其他工具。安装并打开 Thonny。
2. 在解释器设置中选择适合板子的 MicroPython（ESP32）解释器，并选择实际 USB 串口。不同 Thonny 版本菜单位置可能稍有不同。不要点击“安装/更新 MicroPython”替换底层固件。
3. 点击停止，必要时在 Shell 按 `Ctrl+C`，直到出现 `>>>`。输入 `import sys; print(sys.implementation)`，应能确认 MicroPython。不能进入 REPL 时，先处理连接问题，不继续覆盖文件。
4. 打开“文件”视图，将设备上已有的 `boot.py`、`main.py`、`rokicar_core.py`、`rokicar_config.json` 下载到电脑的备份文件夹；没有的文件可以略过。保留其他原厂文件。
5. 将本包的 `boot.py` 保存到设备根目录，随后保存 `rokicar_core.py` 和 `main.py`。三个文件名必须准确，不要变成 `main.py.txt`，也不要只复制外层 `01_固件` 文件夹。设备文件系统的显示路径可能是 `/` 或 `/flash`，应放到已有启动文件所在的根目录。
6. 如果旧程序的看门狗导致反复重启，不要在持续断连状态下继续上传。先重新连接并尝试中断；仍不稳定时按该板官方恢复流程恢复可用 REPL，再上传。不要自行猜测烧录偏移或擦除指令。
7. 上传完成后，重新从设备下载这三份文件到另一个文件夹，与本地原文件比较内容或 SHA-256。只看到“保存成功”还不够。
8. 关闭串口连接，按复位键或断电重启。搜索热点 `RokiCar`，密码 `12345678`；Android App 连接地址为 `ws://192.168.4.1/ws`。

## 方式二：命令行 / AI 操作

在 Windows PowerShell 中，先安装工具并找串口。下例 `COM5` 仅是示例，必须换成实际端口：

```powershell
py -m pip install --upgrade mpremote
py -m mpremote connect list
py -m mpremote connect COM5 resume exec "import sys; print(sys.implementation)"
py -m mpremote connect COM5 resume fs ls
```

进入本仓库主固件目录 文件夹后操作。先建立电脑备份目录，再逐份下载设备上已有文件；不存在的文件记录为“不存在”，不能把串口连接错误也当成“文件不存在”：

```powershell
New-Item -ItemType Directory -Path .\backup -Force
py -m mpremote connect COM5 resume fs cp :boot.py .\backup\boot.py
py -m mpremote connect COM5 resume fs cp :main.py .\backup\main.py
py -m mpremote connect COM5 resume fs cp :rokicar_core.py .\backup\rokicar_core.py
py -m mpremote connect COM5 resume fs cp :rokicar_config.json .\backup\rokicar_config.json
```

确认连接稳定、备份已完成，再上传。保留原校准 JSON，不用默认参数覆盖作者已有标定：

```powershell
py -m mpremote connect COM5 resume fs cp boot.py :boot.py
py -m mpremote connect COM5 soft-reset fs cp rokicar_core.py :rokicar_core.py + fs cp main.py :main.py
```

`soft-reset` 从 raw REPL 发起时不自动运行 `main.py`，便于传文件；旧版本工具的 `resume` 用于跳过自动软复位。工具和板子若在软复位后重新枚举 USB，需要重新查询端口再连接，不能坚持使用已消失的端口。命令格式可查 [官方 mpremote 文档](https://docs.micropython.org/en/latest/reference/mpremote.html)。

回读并比对，任何一项失败都不要宣称刷写完成：

```powershell
New-Item -ItemType Directory -Path .\readback -Force
py -m mpremote connect COM5 soft-reset fs cp :boot.py .\readback\boot.py + fs cp :main.py .\readback\main.py + fs cp :rokicar_core.py .\readback\rokicar_core.py
foreach ($name in @('boot.py','main.py','rokicar_core.py')) {
    $sourceHash = (Get-FileHash -LiteralPath (Join-Path . $name) -Algorithm SHA256).Hash
    $deviceHash = (Get-FileHash -LiteralPath (Join-Path .\readback $name) -Algorithm SHA256).Hash
    if ($sourceHash -ne $deviceHash) { throw "回读校验失败：$name" }
    Write-Host "一致：$name"
}
py -m mpremote connect COM5 resume reset
```

若上传中断，重新连接并上传失败的文件，保持三份文件来自同一版本。若需恢复，上传备份中的辅助文件、主程序及启动文件，再硬复位；原先不存在的文件与原厂恢复方法按备份记录处理，不随意删除整个文件系统。

## 怎样才算成功

- 三份程序在正确根目录，回读内容与本地逐份一致。
- 关闭上传工具后断电重启，能重新找到 `RokiCar` 热点，并能在 App 建立连接。
- 架空状态逐台测试电机，完成轮位、方向、最低稳定起转值与轮速增益校准，确认前进、横移和旋转正确。
- 验证松手停车、急停和连接中断后停车，再低速落地。

“文件写入成功”“程序启动成功”“实车动作正确”是三个不同验收步骤。文件比对不能替代实车验证。本次整理完成了本地语法、依赖及启动文件回归检查，未连接实车执行刷写。

## 常见问题

| 现象 | 怎么处理 |
|---|---|
| 没有 COM 端口 | 数据线、USB 口、设备管理器硬件 ID 与驱动逐项检查 |
| Access denied / 端口被占用 | 关闭 Thonny、串口监视器或另一个 AI 使用的进程，仅保留一个连接 |
| 提示找不到 `rokicar_core` | 核对辅助文件是否在设备根目录、文件名及回读内容 |
| 上传后不自动启动 | 硬复位；检查三份文件路径、标准启动文件及 Shell 错误信息 |
| 反复重启 / 看门狗报错 | 不继续盲写；恢复稳定 REPL，再检查旧启动器、供电与主程序报错 |
| 没有热点 | 先看串口报错，确认兼容 MicroPython 与供电，不先改引脚 |
| 电机轮位不对 | 架空三轮使用 App 标定，不靠换程序猜方向 |
